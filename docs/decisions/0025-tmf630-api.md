# 0025. The TMF630 generic API (`/api/v2`) and the frozen `/api/v1`

Workstream 3G, Step 3 (2026-10-22). Contracts 10, 15; plan Step 3.

## What was built

- **Requirements matrix.** `docs/conformance/TMF630@5.0.0.yaml`: 710 rows, one per normative statement of TMF630 v5.0.0 Parts 1 and 4 to 8 and v4.0.0 Parts 2 and 3, each citing part, section and page, paraphrased (TM Forum member material is never copied). Each row's `note` says how STD relates to it (a Contracts section, an exclusion, client-side, spec-authoring, hubs, tmf-apis, or gap) and names any contradiction with Contracts 10. 123 rows are `tested`, 23 `excluded` by Martin's accepted exclusions (E14, E15, E16, E17, E19, whose `rows` list them), 564 `pending`. The rows were drafted per part by helper agents from the text and checked against it; contradictions with Contracts 10 were verified in the text before they were reported.
- **API names** (10.2). A field's v2 name is its definition name in lowerCamelCase; system fields are `id`, `revision`, `creationDate`, `createdBy`, `lastUpdate`, `updatedBy`. Change sets refuse a field whose v2 name is reserved (`href`, `version`, `withheld`, the system names, anything starting with `@`) or equal to another live field's in its hierarchy, with `DefinitionInvalid` `apiNameClash`. A table's v2 collection name is its qualified name in lowerCamelCase (`helpdesk.ticket_note` is `helpdeskTicketNote`) and its type name the same in UpperCamelCase (`HelpdeskTicketNote`); change sets refuse a table whose v2 name equals another live table's (`foo_bar.baz` and `foo.bar_baz`) or a fixed resource's (`session`, `tableMetadata`, `hub`, `listener`, `checkFormState`, `applyChangeSet`, `openapi`).
- **`/api/v2`** (`packages/server/src/http/v2/`): raw `HttpRouter` routes over the same record service, read compiler and stale-request check as v1. Lists, reads, creates (polymorphic through a parent), merge-patch and JSON Patch evaluated against the locked record, deletes, history as `ChangeEntry`, sessions, table metadata with `schema.json`, and an OpenAPI 3.1 document. Every error is a TMF `Error`.
- **`/api/v1` frozen.** Every response under `/api/v1` carries `Deprecation: @<V1_DEPRECATED_AT>` (RFC 9745) and `Link: </api/v2>; rel="successor-version"`, server-boundary failures included. Its OpenAPI document is `v0.0.2`'s byte for byte apart from the version string (`v1-frozen` pins its hash): change-set refusals reach v1 with v0.0.2's problem codes (`apiNameClash` becomes `invalidName`). The session cookie's path is `/api`.

## Martin's decisions (2026-10-22)

1. **Baseline.** TMF630's verified baseline is v5.0.0 Parts 1 and 4 to 8 plus v4.0.0 Parts 2 and 3 (v5 Parts 2 and 3 are unpublished), not v4.2.0. The matrix file is `TMF630@5.0.0.yaml`. (The reference material had only Parts 2 and 3 of the v4.2.0 bundle; its Part 1 and Parts 4 to 7 had been dropped as superseded.)
2. **M2: stale `If-Match`.** On `/api/v2` (and later the TMF APIs) a stale `If-Match` answers `412 Precondition Failed` with the current version in `ETag`; a missing one where it is required answers `428`. `/api/v1` keeps `409`. `If-Match` stays required on v2 `PATCH` and `DELETE` (decision 0021). The status is one constant, `STALE_VERSION_STATUS` in `http/v2/tmf-error.ts`.
3. **M3: v5 naming, not an exclusion.** `/api/v2` follows TMF630 v5.0.0 Part 1 §2.5 p.22: collections lowerCamelCase, type names UpperCamelCase, derived from the qualified name; the inverse is a lookup over the snapshot's live tables (`http/v2/table-names.ts`), never a parse. Clashes are refused at definition validation (above), which replaces the old argument that fixed names never contain a dot. Renaming a table (or its namespace) changes its v2 names like any rename; a request built before the rename names a collection that no longer exists and gets `UnknownTable`, exactly as a v1 request naming the old qualified name does (6.4 resolves the table at C before the scope check). v1 paths keep the qualified names.

## Applied from the spec check (decision 0026, "Proposed changes to Contracts 10")

Where the v5 text supports them: `.eq` and the URL-encoded comparison forms, `;` as a third OR form, no `.exact` (F630-10); `count=false` drops `X-Total-Count` only on cursor pages, offset pages always carry both counts (F630-12); `Link` with `self`, `first`, `prev`, `next`, `last` on offset pages and `self`, `prev`, `next` on cursor pages (F630-13); negative offset and non-positive or over-1,000 limits are 400, an offset past the end is an empty 200, `after` with `before` selects a range (F630-14); `+name` in `sort` (F630-15); an unchanged `@type`, `@baseType` or `@schemaLocation` in a merge-patch is accepted, a different one is `ReadOnlyField`, a malformed JSON Patch is 400 (F630-17); a `DELETE` with a body is 400 (F630-18); `ChangeEntry` has `@baseType` `History`, `revision`, `action`, `creationDate`, `revisedBy` (F630-23); the counter is `revision`, so `version` keeps TMF's meaning (F630-25); `creationDate` and `lastUpdate` (F630-29); empty attributes are left out (F630-08); every `Error` has `@schemaLocation` (`/api/v2/openapi.json#/components/schemas/<tag>`) and a string `status` (F630-06); a JSONPath `filter` is `501 NotImplemented` (F630-26); a record read through a parent collection carries `Content-Location` with its own URI (F630-31); `fields=none`, `!name` exclusions, `409 FieldsConflict` for including and excluding one attribute, a leading `.` to name an attribute whose name is a directive (F630-11); the fixed task resources are `checkFormState` and `applyChangeSet` (F630-19, names only so far, see Deferred).

Not applied: F630-28 (always emit `@referredType`): an EntityRef to a target the caller cannot see, whose declared class the caller does not know, would name a class the caller cannot know (3.4); Contracts 10.2 keeps leaving `@referredType` and `href` out there. Reserving `type` (F630-29): `core.field` has a platform field named `type`, so reserving it would refuse the core set; v2 shows it as `type`.

## Contradictions between the TMF630 text and Contracts 10 (as first reported; Martin decided them below)

Verified in the text. The first four are in the v4.0.0 Parts 2 and 3 baseline; Contracts 10's rule was built because it keeps the Step 0 to 2 guarantees, and each needs Martin's decision or an exclusion.

1. **Base-collection reads return concrete representations** (v4.0.0 Part 2 §1 p.4): Contracts 2.3 and 10.2 show only the endpoint's lineage fields through a parent collection; `@type` and `Content-Location` say where the rest is.
2. **Operations relative to the base type, and `href` through it** (Part 2 §1 p.5, SHOULD; and the request URL identifies the resource, Part 3 §2.5 p.14): `href` is the concrete class's URI. Part 2 also says an entity MUST declare its alternative URI in a header: `Content-Location` now does.
3. **An extension schema includes every base attribute** (Part 2 §2.1 p.11, MUST): `schema.json` is the caller's and names no field the caller cannot read, so a child class's schema can omit an inherited field a deny on the child hides.
4. **An EntityRef has `id` and `href`** (Part 2 §4 p.25, §5 p.32, MUST; v5 Part 7 §1.4.2 p.14 also requires `@referredType`): STD leaves `href` and `@referredType` out when the caller can neither see the target nor know the declared class (F630-28 above).
5. **v5 Part 1** (each a SHOULD or MUST against Contracts 3.8 or 10): caching should be encouraged and GET 200s carry expiration headers (§1.5.1 p.11) against `Cache-Control: no-store` on every API response (decision 0018); 403 outside the permitted scope and 410 for a gone resource (§3.3.3 pp.31-32) against identical 404s (3.4, 3.8); 206 for partial or range paging (§3.3.1 p.30; STD offers no range paging and never answers 206); history as `History` resources with `history/{id}` and the same filters as collections (§12 pp.206-214) against 3.7's history filters; free-text filters compare values unmodified (§13.2.3 p.242) against the field's key (5.5); task names are verbs (§2.5 p.22, §9.1 p.138; renamed, see Deferred).
6. **v5 Parts 4, 5, 7**: `version` is a semver string (Part 4 §3.4 p.30; resolved by `revision`); JSON Patch Query with unsupported JSON Path is 501 (Part 5 §4 p.9) against 415 for the media type (exclusion E15 keeps it out); a typed `[Entity]Ref` where the type is known (Part 7 §1.4.3 p.15) against STD's single `EntityRef`.

## Martin's decisions on the contradictions (2026-10-22)

- **D1, concrete representation through a parent collection** (resolves 1): `/api/v2/helpdeskTicket/{id}` for an incident returns the incident's own representation (its `@type`, its fields), with field rules hiding what the caller cannot read, as on the concrete collection; lists through a parent likewise. Built: `concreteRecords` reads each child-class record again through its own class's view (`readByIds`), one query per class on a page. An explicit `fields` still names the parent's attributes. Contracts 2.3 and 10.2 say so; v1 is unchanged.
- **D2, information hiding wins**, each a narrow exclusion Martin accepted (`docs/conformance/decisions.yaml`): `X630-hidden-base-fields` (3), `X630-referred-type-hidden` (4; v5 Part 7 makes `href` optional, `@referredType` is the real conflict), `X630-identical-404` (403 and 410 in 5), `X630-no-store` (caching in 5; Part 1 §1.5.1 permits discouraging it).
- **D3, the history pattern**: history lists page (`offset`, `limit`, both counts, `Link`), filter on ChangeEntry attributes (`action`, `kind`, `revision`, `creationDate`, `revisedBy.id`, plus 3.7's filters), select with `fields`, and `history/{changeId}` returns one entry; every entry has an `href`. The per-caller filtering of 3.7 and 4.4–4.5 is unchanged; a filter never reads record values.
- **D4, case**: v2's TMF attribute filters compare text unmodified (case-sensitive), as v5 Part 1 §13.2.3 p.242 asks; `/api/v1`, the browser and v2's `condition` keep each field's configured case behavior, so a v2 caller matches case-insensitively with `condition` (`condition=name = "alice"`). The shared compiler is unchanged for v1: the TMF part compiles separately through a class view whose text fields are case-sensitive (`compileFilterExpr` option `exactText`), with its own join aliases.

The reviewer's recommendations, applied: base operations stay (reads, polymorphic creates, updates and deletes through a parent collection) with the canonical concrete `href`; every single-resource response carries `Link: <requested URI>; rel="self", <href>; rel="canonical"` and, through a parent, `Content-Location` (v4.0.0 Part 3 §2.5 p.14, Part 2 §1 p.5); field selection and paging answer 200 (no range paging, so never 206); `revision` stays; an unsupported patch-query media type stays 415 under E15; references are typed (`CoreUserRef`, `<Type>Ref`) when the caller knows the field's declared target class, else the generic `EntityRef` (v5 Part 7 §1.4.3 p.15); `type` is reserved and `core.field`'s `type` is `fieldType` in v2; the JSON Patch evaluator (`planJsonPatch`, `applyJsonPatch` and `UpdateInput.evaluate`) is the one the TMF adapters reuse.

## Review round 1 (fixes)

1. **Legacy cookie** (F1): cookie sign-in and sign-out, v1 and v2, also expire `std_session` at `Path=/api/v1`; a request carrying two `std_session` cookies is not authenticated by cookie (bearer still wins). Migration: after the upgrade the first sign-in or sign-out removes the legacy cookie; until then a lone legacy cookie still authenticates `/api/v1` only.
2. **Polymorphic create staleness** (F2): the created class is resolved from `@type` first, then the stale check (6.4) runs for that class, its newly required fields included.
3. **Merge into an unreadable json field** (F3): the merge uses the stored value from the locked record (`LockedImage.storedJson`); write authorization is unchanged and the response withholds the value.
4. **Exclusion staleness** (F4): `fields=!name` is checked as the default selection at R minus the exclusions (`ScopeParameters.excluded`); `none` checks no selection.
5. **OpenAPI** (F5): `/api/v2/openapi.json` is `OpenApi.fromApi(StdApiV2)`, the shared definition in `packages/api/src/v2/`, with separate `ResourceCreate`, `ResourcePatch` and `Resource` schemas and every error subtype under `#/components/schemas/<Tag>`; the server keeps its raw routes.
6. **JSON Patch image** (F6): the image carries `id`, `href`, `@type`, `@baseType`, `@schemaLocation` and `revision`; writing them stays `ReadOnlyField`.
7. **405** (F7): every resource shape answers the methods it does not offer with `405` and an accurate `Allow`, decided by the path's shape after the session and before any table or record is looked up, so a caller gets the same 405 for a visible, hidden or missing record.
8. **Names** (F8): a v2 name splits the definition name at runs of underscores (`due__date` and `due_date` are both `dueDate`, `foo_` is `foo`); clashes are checked on these names; v1 names are unchanged.
9. **Matrix and tests** (F9): the list-ETag row is pending again; the suites gained the proving cases listed in the round's report.

## Review round 2 (fixes)

1. **Concrete staleness**: through a parent collection, each concrete class's default selection is checked against the request's stated revision before its records are read again (`concreteRecords`), only for the classes of records the caller can see; a read or list through the parent is `SchemaChanged` exactly when the child collection is. Proved by `v2-review-2` R2-1.
2. **Contract** (closes F5): `GET /session/current` has its own response schema (`CurrentSession`: user, name, roles, schema revision, no token or expiry); reads document `409` (`FieldsConflict`, `SchemaChanged`); a `ChangeEntry` selected with `fields` needs only its identity members. The server checks every request body against the shared request schemas before reading it (`request-schemas.ts`: `ResourceCreate`, `ResourcePatch`, `JsonPatchOperation[]`, `SessionCreate`; refused is `400 InvalidRequest`). The test client checks every `/api/v2` response of every suite against the shared definition (`packages/testing/src/v2-contract.ts`: the endpoint by method and path, a documented status, a body of that status's schemas; a defect, `500` without a body, is not checked), and `v2-contract` drives every endpoint to a success and an error. The first full run found the three schema gaps above and nothing else.
3. **Typed references in `schema.json`**: each reference attribute, `createdBy` and `updatedBy` point at `#/$defs/<Type>Ref` when the caller knows the declared target, else `#/$defs/EntityRef`, by the same rule as the resources (`refTypeOf`); the schema defines only those types. R2-3 validates every resource Alice, Bob and Ada list against its `@schemaLocation` (Ajv, JSON Schema 2020-12) and checks that no definition names a table the caller does not know.
4. **History links**: single-resource answers carry `version-history` and `latest-version`; history lists `latest-version`; one entry `self`, `version-history`, `latest-version`, `predecessor-version` and `successor-version` (TMF630 v5.0.0 P1 §12.3 p.210, §12.3.3 pp.231-232, §12.4 p.238). All come from the entries the caller may see. Under 3.7 every entry of a live record the caller can read is visible to that caller (field changes are left out, the entry is not), so the hidden case is a record the caller cannot see, whose resource and entries answer the identical `NotFound` with no `Link` (R2-4); a deleted record's history is admin-only (3.7).
5. **Methods by resource route**: the routes serve `GET`, `HEAD` (as `GET` without a body, wherever `GET` is), `POST`, `PATCH` and `DELETE` as each route offers them; every other method (`OPTIONS`, `PUT`, `TRACE`, `PROPFIND` and the rest the router knows) reaches a catch-all that answers by the path's resource route: `OPTIONS` `204` with `Allow`, anything else `405` with `Allow`, both after the session except on `/session` and `/openapi.json`, an unknown path `NotFound`. `Allow` now lists `HEAD` and `OPTIONS`. R2-5 checks visible, hidden and missing records give byte-identical `OPTIONS`, `PUT` and `PROPFIND` answers, and identical `HEAD` 404s. [judgment: `OPTIONS` needs a session like `405`; STD serves no cross-origin callers]
6. **Minor**: `v2-openapi` decodes with `Schema.decodeUnknownEffect` inside its Effect generators.

## Review round 3 (fixes)

The reviewer accepted that `OPTIONS` needs a session (TMF630 v5.0.0 P1 §1.6 pp.15-17, §3.1 p.26), on condition that it authenticates.

1. **Authenticated method answers**: `OPTIONS` and `405` on a protected route now run `asActor` in a request transaction, as every other route does, before answering; `withSession` alone only read the token, so an invalid token got `204` or `405` with `Allow`. An invalid, revoked or expired session is `401 Unauthenticated` without `Allow`; `/session` and `/openapi.json` stay public; no table or record is looked up. Proved by `v2-review-2` R3-1.
2. **`latest-version` of a history list**: it is the last entry the caller may see, read without the list's filters (the record service's `kind`, `since`, `until`, `actor`, `field` and the ChangeEntry filters) and paging, so `?kind=create` and `?action=created` link the same current revision, and a filter that selects nothing keeps the link; filtered paging and counts are unchanged. Proved by R3-2.
3. **Minor**: `v2-openapi` decodes its typed fixture literals with `Schema.decodeEffect` and response JSON with `Schema.decodeUnknownEffect`.

## Judgments

- `href` uses `STD_PUBLIC_URL`'s origin when set, else the request's `Host` over `http` for loopback and `https` otherwise, as the cookie's `Secure` rule does.
- A page asked for with `offset` is an offset page; any other (the first, or a cursor page) is a cursor page whose `next` is a cursor: keyset paging is the stable one (3.5).
- Escaping in filter values: a backslash escapes `,`, `;` and itself.
- A date-only value on a date-time attribute: equality means the UTC day, a comparison its first instant (Part 1 §4.4 p.57 allows shortened values).
- In filters, `<ref>.id` is the reference itself and `<ref>.<attr>` a one-hop path; in `fields`, `<ref>.id` and `<ref>.name` select the reference (its EntityRef has both) and `<ref>.<attr>` adds that member to the EntityRef.
- A `test` on a reference compares the EntityRef's `id` only; a JSON Patch image leaves empty and withheld attributes out, so `replace` of an empty attribute fails like a missing path (use `add`).
- A JSON Patch that does not apply (a failed `test`, or a path an operation reads or removes that is not there) is `409 PatchTestFailed` naming the operation's index.
- An unknown query parameter that has the shape of an attribute filter is resolved as one (`UnknownField`, identical for hidden and missing); one that does not (`@foo`, three segments) is `InvalidRequest`.
- `PUT` is `405` with `Allow`; an unknown `/api/v2` path is a TMF `NotFound`.
- `V1_DEPRECATED_AT` is a placeholder (2026-10-22T00:00:00Z) until `v0.0.3` is tagged; the release commit sets it to the tag's commit time (`git log -1 --format=%ct v0.0.3`).

## API consolidation (Martin, 2026-10-23)

Martin decided on 2026-10-23 (decision 0021, decision 56) that STD has one API: STD is greenfield and nobody uses the old API, so the old `/api/v1` is retired and deleted and the TMF630 API becomes STD's only API, renamed from `/api/v2` to `/api/v1`. This supersedes decision 0021's decision 6 and the strict freeze recorded above. Workstream `ws/api-v1-consolidation` carries it out in three phases.

**Phase 1: the new API serves everything the old one did.**

- `applyChangeSet` (`POST /api/v2/applyChangeSet`, `GET /api/v2/applyChangeSet/{id}`): a task resource over the same change-set service (`change-set-requests.ts`, shared with the old route). `201` with `Location` when a change set was recorded, `200` with `state: unchanged` when nothing changed; the body is checked against the shared `ApplyChangeSetCreate`; refusals are TMF `Error`s with the current problem codes. Record rules (`createRecordRule` and the rest) go through it as through the old route.
- Writes to definition tables through `/api/v2/{table}` (`coreRole`, `coreAccessRule`, `coreRecordRule`, `coreChoice`, `coreLayout`, `coreSavedFilter`, `coreField`, and every other kind of `DEFINITION_KIND_OF_TABLE`): each is a one-operation change set as on the old API (Contracts 1.4). The body uses v2 attribute names; `PATCH` takes a merge patch with `If-Match` (a JSON Patch is `415`, since a definition is not a locked record image); `DELETE` answers `204`. The definition tables are found by their fixed v2 collection names, since platform tables are never renamed. The `405` for definition-table writes is gone.
- `allowedFor=<collection>/<attribute>` on lists: a reference picker's allowed-records condition (decision 0020), with the old semantics and refusals that name what the request said.
- Table metadata in v2 terms: list entries carry the qualified `name`, metadata carries `resourceType`, and saved filters' `filter` text uses v2 names, as `condition` takes it.
- The typed client `makeStdClientV2` (`packages/api/src/v2/client.ts`) is derived from the shared definition; the web app moves onto it (workstream `ws/web-new-api`).
