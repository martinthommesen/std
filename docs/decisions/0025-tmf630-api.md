# 0025. The TMF630 generic API (`/api/v2`) and the frozen `/api/v1`

Workstream 3G, Step 3 (2026-10-22). Contracts 10, 15; plan Step 3.

## What was built

- **Requirements matrix.** `docs/conformance/TMF630@5.0.0.yaml`: 710 rows, one per normative statement of TMF630 v5.0.0 Parts 1 and 4 to 8 and v4.0.0 Parts 2 and 3, each citing part, section and page, paraphrased (TM Forum member material is never copied). Each row's `note` says how STD relates to it (a Contracts section, an exclusion, client-side, spec-authoring, hubs, tmf-apis, or gap) and names any contradiction with Contracts 10. 123 rows are `tested`, 23 `excluded` by Martin's accepted exclusions (E14, E15, E16, E17, E19, whose `rows` list them), 564 `pending`. The rows were drafted per part by helper agents from the text and checked against it; contradictions with Contracts 10 were verified in the text before they were reported.
- **API names** (10.2). A field's v2 name is its definition name in lowerCamelCase; system fields are `id`, `revision`, `creationDate`, `createdBy`, `lastUpdate`, `updatedBy`. Change sets refuse a field whose v2 name is reserved (`href`, `version`, `withheld`, the system names, anything starting with `@`) or equal to another live field's in its hierarchy, with `DefinitionInvalid` `apiNameClash`. A table's v2 collection name is its qualified name in lowerCamelCase (`helpdesk.ticket_note` is `helpdeskTicketNote`) and its type name the same in UpperCamelCase (`HelpdeskTicketNote`); change sets refuse a table whose v2 name equals another live table's (`foo_bar.baz` and `foo.bar_baz`) or a fixed resource's (`session`, `tableMetadata`, `hub`, `listener`, `checkFormState`, `applyChangeSet`, `openapi`).
- **`/api/v2`** (`packages/server/src/http/v2/`): raw `HttpRouter` routes over the same record service, read compiler and stale-request check as v1. Lists, reads, creates (polymorphic through a parent), merge-patch and JSON Patch evaluated against the locked record, deletes, history as `ChangeEntry`, sessions, table metadata with `schema.json`, and an OpenAPI 3.1 document. Every error is a TMF `Error`.
- **`/api/v1` frozen.** Every response under `/api/v1` carries `Deprecation: @<V1_DEPRECATED_AT>` (RFC 9745) and `Link: </api/v2>; rel="successor-version"`, server-boundary failures included. Its OpenAPI document is `v0.0.2`'s byte for byte apart from the version string (`v1-frozen` pins its hash): change-set refusals reach v1 with v0.0.2's problem codes (`apiNameClash` becomes `invalidName`). The session cookie's path is `/api`.

## Martin's decisions (2026-10-22)

1. **Baseline.** TMF630's verified baseline is v5.0.0 Parts 1 and 4 to 8 plus v4.0.0 Parts 2 and 3 (v5 Parts 2 and 3 are unpublished), not v4.2.0. The matrix file is `TMF630@5.0.0.yaml`. (The reference material had only Parts 2 and 3 of the v4.2.0 bundle; its Part 1 and Parts 4 to 7 had been dropped as superseded.)
2. **M2: stale `If-Match`.** On `/api/v2` (and later the TMF APIs) a stale `If-Match` answers `412 Precondition Failed` with the current version in `ETag`; a missing one where it is required answers `428`. `/api/v1` keeps `409`. `If-Match` stays required on v2 `PATCH` and `DELETE` (decision 0021). The status is one constant, `STALE_VERSION_STATUS` in `http/v2/tmf-error.ts`.
3. **M3: v5 naming, not an exclusion.** `/api/v2` follows TMF630 v5.0.0 Part 1 §2.5 p.22: collections lowerCamelCase, type names UpperCamelCase, derived from the qualified name; the inverse is a lookup over the snapshot's live tables (`http/v2/table-names.ts`), never a parse. Clashes are refused at definition validation (above), which replaces the old argument that fixed names never contain a dot. Renaming a table (or its namespace) changes its v2 names like any rename; a request built before the rename names a collection that no longer exists and gets `UnknownTable`, exactly as a v1 request naming the old qualified name does (6.4 resolves the table at C before the scope check). v1 paths keep the qualified names.

## Applied from the spec check (decision 0026, "Proposed changes to Contracts 10")

Where the v5 text supports them: `.eq` and the URL-encoded comparison forms, `;` as a third OR form, no `.exact` (F630-10); `count=false` drops `X-Total-Count` only on cursor pages, offset pages always carry both counts (F630-12); `Link` with `self`, `first`, `prev`, `next`, `last` on offset pages and `self`, `prev`, `next` on cursor pages (F630-13); negative offset and non-positive or over-1,000 limits are 400, an offset past the end is an empty 200, `after` with `before` selects a range (F630-14); `+name` in `sort` (F630-15); an unchanged `@type`, `@baseType` or `@schemaLocation` in a merge-patch is accepted, a different one is `ReadOnlyField`, a malformed JSON Patch is 400 (F630-17); a `DELETE` with a body is 400 (F630-18); `ChangeEntry` has `@baseType` `History`, `revision`, `action`, `creationDate`, `revisedBy` (F630-23); the counter is `revision`, so `version` keeps TMF's meaning (F630-25); `creationDate` and `lastUpdate` (F630-29); empty attributes are left out (F630-08); every `Error` has `@schemaLocation` (`/api/v2/openapi.json#/components/schemas/<tag>`) and a string `status` (F630-06); a JSONPath `filter` is `501 NotImplemented` (F630-26); a record read through a parent collection carries `Content-Location` with its own URI (F630-31); `fields=none`, `!name` exclusions, `409 FieldsConflict` for including and excluding one attribute, a leading `.` to name an attribute whose name is a directive (F630-11); the fixed task resources are `checkFormState` and `applyChangeSet` (F630-19, names only so far, see Deferred).

Not applied: F630-28 (always emit `@referredType`): an EntityRef to a target the caller cannot see, whose declared class the caller does not know, would name a class the caller cannot know (3.4); Contracts 10.2 keeps leaving `@referredType` and `href` out there. Reserving `type` (F630-29): `core.field` has a platform field named `type`, so reserving it would refuse the core set; v2 shows it as `type`.

## Contradictions between the TMF630 text and Contracts 10 (reported, not silently followed)

Verified in the text. The first four are in the v4.0.0 Parts 2 and 3 baseline; Contracts 10's rule was built because it keeps the Step 0 to 2 guarantees, and each needs Martin's decision or an exclusion.

1. **Base-collection reads return concrete representations** (v4.0.0 Part 2 §1 p.4): Contracts 2.3 and 10.2 show only the endpoint's lineage fields through a parent collection; `@type` and `Content-Location` say where the rest is.
2. **Operations relative to the base type, and `href` through it** (Part 2 §1 p.5, SHOULD; and the request URL identifies the resource, Part 3 §2.5 p.14): `href` is the concrete class's URI. Part 2 also says an entity MUST declare its alternative URI in a header: `Content-Location` now does.
3. **An extension schema includes every base attribute** (Part 2 §2.1 p.11, MUST): `schema.json` is the caller's and names no field the caller cannot read, so a child class's schema can omit an inherited field a deny on the child hides.
4. **An EntityRef has `id` and `href`** (Part 2 §4 p.25, §5 p.32, MUST; v5 Part 7 §1.4.2 p.14 also requires `@referredType`): STD leaves `href` and `@referredType` out when the caller can neither see the target nor know the declared class (F630-28 above).
5. **v5 Part 1** (each a SHOULD or MUST against Contracts 3.8 or 10): caching should be encouraged and GET 200s carry expiration headers (§1.5.1 p.11) against `Cache-Control: no-store` on every API response (decision 0018); 403 outside the permitted scope and 410 for a gone resource (§3.3.3 pp.31-32) against identical 404s (3.4, 3.8); 206 for partial or range paging (§3.3.1 p.30; STD offers no range paging and never answers 206); history as `History` resources with `history/{id}` and the same filters as collections (§12 pp.206-214) against 3.7's history filters; free-text filters compare values unmodified (§13.2.3 p.242) against the field's key (5.5); task names are verbs (§2.5 p.22, §9.1 p.138; renamed, see Deferred).
6. **v5 Parts 4, 5, 7**: `version` is a semver string (Part 4 §3.4 p.30; resolved by `revision`); JSON Patch Query with unsupported JSON Path is 501 (Part 5 §4 p.9) against 415 for the media type (exclusion E15 keeps it out); a typed `[Entity]Ref` where the type is known (Part 7 §1.4.3 p.15) against STD's single `EntityRef`.

## Within the contracts

- **`json-patch-race` without `If-Match`.** Contracts 10.5 requires `If-Match` on the generic API, while the test it names races two patches without it. Both hold here: the record service evaluates patches after the lock with or without a version (`UpdateInput.evaluate`, `expectedVersion` null for the TMF APIs, 11.1), and `json-patch-race` proves it there (one `PatchTestFailed`, nothing written; a copy sees the version it applies to); through `/api/v2` two patches on one revision give one 200 and one 412. ## Judgments

- `href` uses `STD_PUBLIC_URL`'s origin when set, else the request's `Host` over `http` for loopback and `https` otherwise, as the cookie's `Secure` rule does.
- A page asked for with `offset` is an offset page; any other (the first, or a cursor page) is a cursor page whose `next` is a cursor: keyset paging is the stable one (3.5).
- Escaping in filter values: a backslash escapes `,`, `;` and itself.
- A date-only value on a date-time attribute: equality means the UTC day, a comparison its first instant (Part 1 §4.4 p.57 allows shortened values).
- In filters, `<ref>.id` is the reference itself and `<ref>.<attr>` a one-hop path; in `fields`, `<ref>.id` and `<ref>.name` select the reference (its EntityRef has both) and `<ref>.<attr>` adds that member to the EntityRef.
- A `test` on a reference compares the EntityRef's `id` only; a JSON Patch image leaves empty and withheld attributes out, so `replace` of an empty attribute fails like a missing path (use `add`).
- A JSON Patch that does not apply (a failed `test`, or a path an operation reads or removes that is not there) is `409 PatchTestFailed` naming the operation's index.
- An unknown query parameter that has the shape of an attribute filter is resolved as one (`UnknownField`, identical for hidden and missing); one that does not (`@foo`, three segments) is `InvalidRequest`.
- `PUT` is `405` with `Allow`; an unknown `/api/v2` path is a TMF `NotFound`.
- `V1_DEPRECATED_AT` is a placeholder (2026-10-22T00:00:00Z) until `v0.0.3` is tagged; the release commit sets it to the tag's commit time (`git log -1 --format=%ct v0.0.3`).

## Deferred (reported)

- `POST /api/v2/applyChangeSet` and `GET .../applyChangeSet/{id}` (the v1 change-set endpoint moved to a task resource) and writes to definition tables through `/api/v2/{table}` (answered `405` with `Allow: GET`): v1 serves both until then.
- `POST /api/v2/checkFormState`: there is no form-state endpoint in v1 yet; workstream 3C builds it.
- Sorting by one-hop paths (F630-15); a per-table OpenAPI document for v2 (the table's `schema.json` and `/api/v2/openapi.json` describe it); `GET .../history/{id}`.
- The Contracts 3 suites run on v2 as `contracts3-v2` (their scenarios restated in v2's terms), not by parameterizing every v1 file; `error-fuzz` on v2 and the browser tests on v2 follow with the web app's move to v2.
- The web app keeps using v1 (its move to v2 is a follow-up).
